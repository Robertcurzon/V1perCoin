# V1PER Feast scoring

The frozen menu accepts SHIB, PEPE, SPX and FLOKI on Ethereum; PUMP, PENGU, BONK and WIF on Solana; native DOGE (8 decimals) and native MemeCore M (18 decimals, chain ID 4352). Exact contracts and feeds are in `config.json`. Wrapped substitutes are excluded. The campaign remains closed: windowStart, bindingDeadline and all receiving addresses are unset.

## Reproduce a reviewed allocation

1. Publish a release config with `windowStart=T` in Unix seconds, `bindingDeadline=T+23*86400`, the dated snapshot, exact assets and receiving addresses. Keep the release finality rules. Contributions qualify in `[T,T+21 days)`; bindings must be received by T+23 days, inclusive.
2. Collect source-signed bindings: `chain, windowStart, bindingDeadline, source, sui, message, signature`. The intake operator records `receivedAt` from its archived submission log; a participant's local timestamp is not authoritative. `bindingMessage` includes network, destination, opening and cutoff. Source authentication supports EVM EOA personal_sign, Solana Ed25519 and Dogecoin P2PKH compact messages. No contract wallets or mixed-input DOGE receipts.
3. Optionally collect `lockMonths` (0/12/24) and `suiLockSignature`. The destination Sui wallet signs the exact `suiLockMessage` personal message, independently of its source. Missing/source-only or invalid choices default to liquid and are reported. Different valid choices for the same Sui wallet resolve to liquid; they cannot stop the run. Locked rows with zero Move full_reward become liquid and are reported.
4. Export all inbound receipts, including unbound senders, into `{source, receipts}`. Source provenance is `{provider,datasetId,evidenceSha256,exportedAt}`. Each receipt records chain, contract/native, from, to, amountBaseUnits, confirmedAt, txHash and index. Confirmation time is canonical source-chain time, never fetch time. Normalize hexadecimal transaction hashes to lowercase; EVM uses 0x plus 64 hex digits, DOGE 64 hex digits, Solana a base58 64-byte signature. Duplicate canonical transaction/index pairs stop scoring.
5. Require finalized successful Ethereum chain-1 or MemeCore chain-4352 receipts with blockNumber <= finalizedBlockNumber; Solana finalized commitment and slot <= finalizedSlot; DOGE >=60 confirmations with exclusively bound P2PKH inputs. These fields are externally acquired assertions, not a light-client proof. Never infer an unsupported finality anchor.
6. Independently export each accepted wallet/asset's balances and itemized `outflows` (`txHash,amountBaseUnits,destination,timestamp`). Aggregate outflow totals are forbidden. Transaction hashes must be unique within each wallet/asset. StartAnchor and endAnchor include finalized network fields, distinct blockHash identifiers and timestamps: start strictly before T; end at or after T+21 days. Balance state must represent those exact window boundaries, without unrelated intervening flows. Reconcile `inbound=endBalance-startBalance+sum(outflows)` per asset, including zeros. Native outflows use actual wallet balance reductions, including transaction fees; conservative netting deducts that recorded reduction from a returned source. Adapters must normalize this faithfully; unsupported multi-destination or fee-only exports cannot be scored until an independently reviewed adapter supplies this schema.
7. `score()` always requires `{transferSource,independent}` as its fifth argument and runs reconciliation first; there is no unchecked direct-scoring path. All receiving-wallet sources are rejected. Per source and asset, in-window receiving-wallet returns reduce credited inbound amounts, floored at zero. Deduct returns in canonical chronological transaction/index order before valuing remaining receipts. This prevents repeated circulation from multiplying credit.
8. Acquire historical prices with `fetch_prices.mjs` and operator-only PYTH_BENCHMARKS_API_KEY. Input is `{config,transfers:receipts}`. Output `{prices,rawArchive}` preserves exact `rawResponse` bytes, URL and SHA-256. In-flight results are cached by feed/sample time; requests are serialized and paced at 150 ms. Scoring reparses every response, verifies its hash and requested feed/time, and requires every used observation to match the archive. A hash does not authenticate the remote provider.
9. Create `INPUT_MANIFEST.json`: `{files:{config,bindings,transfers,prices,reconciliation},evidenceFiles:[primaryRaw,independentRaw]}` with paths relative to the manifest. Evidence hashes must match both source descriptors. Run `node scripts/feast/score.mjs INPUT_MANIFEST.json OUTPUT_DIRECTORY` from a clean committed scorer. Every check precedes output creation. Publish the full inputs, result, source evidence, CSV, `allocations.sha256` and `commitment.sha256`.
10. Upload the CSV's positive rows in normalized-address binary order. `set_allocations(pool,cap,addresses,amounts,terms,commitment,rowCount,restart,clock)` starts with restart=true; continuation batches use false with unchanged commitment/count. For an edit, restart and re-upload the complete resulting table. Amount-zero rows (term zero) remove existing entries; they do not enter the hash or positive row count. Finalization requires all current table rows covered, matching commitment/count and seven days since the last batch. Reward capacity is reserved atomically, or finalization aborts.

## Exact valuation and allocation

Pyth integer price/exponent pairs retain all precision. USD value is the lower of spot and the arithmetic mean of the preceding 1,440 one-minute observations. Each observation must be no more than 60 seconds old and never future-dated. The average retains its rational denominator; only the final `amount * usedPrice * 1e8 / assetScale` is floored. Sub-1e-8 prices are supported. USD totals use 1e8 units.

First calculate each receipt's base quantity: `floor(USD_scaled * 10000 * 1e6 / 1e8)`. Then apply timing and Sui-authorized lock bonuses. Days 1–5 are 1.50x; days 6–18 are `(47-day)/28`; days 19–21 are 1.00x. Liquid/12/24 months multiply by 1/1.1/1.25. Denominator 560 carries all combinations exactly. Sum bonus-weighted quantities per wallet. Each allocation is the smaller of its quantity and its proportional share of 100M inventory, rounded down. Unallocated inventory burns at finalization. No wallet cap applies.

CSV uses LF newlines and a fixed header. Its SHA-256 identifies its exact text. The separate on-chain commitment starts with 32 zero bytes and, for each positive row, computes `SHA256(running || BCS(address) || BCS(u64 amount) || BCS(u64 term))`. Addresses are 32 bytes; integers are little-endian. Order, amounts and terms are bound across batches. `allocationRows` counts positive CSV rows. The generated Move fixture proves scorer-to-contract parity; do not use the CSV file hash as the Move commitment.

Clearing price is eligible USD divided by allocated tokens, as an exact fraction. `receivedBaseUnits` contains net eligible contributions; `treasuryReceivedBaseUnits` contains gross accepted inbound receipts, including unbound ones. Both include all ten asset IDs and explicit zeros. Neither is a live balance. Publish exact results.json bytes as public/feast-results.json and configure its file hash; the monitor rejects a commitment/count mismatch with the chain.

## Deadlines, custody and operational gates

Free applications run T-7 to T; approved claims run T to T+14 days. Feast contributions close T+21; binding cutoff is T+23; the complete allocation review starts after intake closes. Allow at least seven days after the final upload before finalization F. Liquid vesting is 50% at F and complete at F+60; all Feast claims expire F+90. Allocation creates an absolute 60-day deadline for scheduling and starting free claims and a 120-day deadline for Feast finalization. Missed deadlines permit anyone to burn inventory; finalizing cannot revive an expired pool. Feast expiry returns unused reserved rewards before burning principal.

Measured on pinned Sui 1.80.1 localnet: see `docs/SECURITY_SPEC.md` for fresh-table gas. The contract limit is 500 rows; use 250 routinely. A 1,000-address pure argument exceeds the 16,384-byte protocol limit. Allow a 2-SUI gas budget for the measured 500-row transaction; production pricing varies. Rehearsal receipts/gas remain CI artifacts.

Founder-controlled V1PER Foundation wallets receive contributions without refunds. 25% of gross accepted proceeds is committed to liquidity, with opening price no lower than clearing price; conversion, paired funding, LP custody/locking and spending are operator commitments, not cross-chain restrictions. No pool, production custody or public intake is created here.

Before opening, run `npm run check:pyth` with authenticated operator access and review its real 30-point archive. Synthetic cases do not establish readiness. Full minute history, four-network canonical export/reconciliation adapters, intake timestamps, provider independence, deployment/source correspondence and actual liquidity/custody need independent review. Internal consistency and signatures do not prove honest source data. No cross-chain indexer, light client, confidential transfer or refund contract is present.
