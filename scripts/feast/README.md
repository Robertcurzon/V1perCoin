# V1PR Feast scoring

The curated accepted list is SHIB, PUMP, PEPE, DOGE, PENGU, SPX, BONK, FLOKI, WIF and MemeCore M in config.json. DOGE is native Dogecoin (eight decimals); M is native MemeCore mainnet, chain ID 4352 (18 decimals). Ethereum and Solana assets use exact contracts. The archived market snapshot is provenance, not an automatic selection rule. Pyth DOGE/USD and M/USD feeds are archived and verified. Wrapped substitutes are not accepted. No campaign is open: windowStart and all four Foundation receiving addresses must come from real launch records.

The V1PR Foundation (founder-controlled) receives contributed coins. Publish Ethereum, Solana, Dogecoin and MemeCore receiving addresses before any signatures or transfers, with chain-appropriate custody. Never substitute a Sui address for a source-chain destination. Native DOGE bindings use P2PKH source addresses; DOGE receiving custody may use P2SH multisig.
## Reproduce

1. Copy config.json to a release config file. Set the real Unix-second `windowStart`, exact assets and published receiving wallets. Keep `finalityRules` unchanged. Publish the config before opening contributions (Trust assumption: receipt publication and freeze are operator duties).
2. Write a bindings JSON array. Each entry has chain, windowStart, source, sui, lockMonths (0/12/24), message, signature and lockSignature. `networks.mjs` defines the two exact messages; both signatures commit the network and campaign start, and the second commits the term. EOA personal-sign, Solana Ed25519 and compact Dogecoin P2PKH signatures are supported. Contract wallets and mixed-source DOGE inputs are unsupported.
3. Archive a complete inbound transfer export, including unbound senders. The transfers file is `{ "source": { "provider": "...", "datasetId": "...", "evidenceSha256": "...", "exportedAt": 0 }, "receipts": [] }`. Source timestamps are positive Unix seconds; the hash identifies the raw archived provider evidence file. Each receipt includes chain, exact contract (or `native`), from, to, amountBaseUnits, confirmedAt, txHash and index. `confirmedAt` is the finalized receipt's canonical block/slot confirmation timestamp, not the operator's fetch time; balance boundaries must use that same timestamp policy.
4. All receipts declare `finalityRule`. Ethereum: `finalized-block`, chainId 1, finalized true, receiptStatus success, blockNumber <= finalizedBlockNumber. Solana: `finalized-slot`, finalized true, successful receipt, commitment finalized, slot <= finalizedSlot. DOGE: `60-confirmations`, at least 60 confirmations, exclusively bound P2PKH inputs and a 64-hex txid/output index. MemeCore: `finalized-block`, chainId 4352, finalized true, successful native-transfer receipt, blockNumber <= independently established finalizedBlockNumber. A provider that cannot establish that anchor is unsupported; do not guess a depth. These are release acceptance rules, not assertions that a supplied Boolean proves finality. See [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/) and [Solana RPC](https://solana.com/docs/rpc).
5. Acquire prices with `fetch_prices.mjs` using an acquisition JSON `{config, transfers: receipts}` and env-only PYTH_BENCHMARKS_API_KEY. The prices file contains both `prices` and `rawArchive`. No estimates or missing/future/stale observations are accepted. Historical authenticated access must pass the pre-opening gate.
6. Independently export balance snapshots and **all outflows** for every receiving wallet and accepted asset, including zero-receipt assets. The reconciliation file has a separate `source` descriptor and `records`: chain, contract, wallet, windowStart, windowEnd, startBalanceBaseUnits, endBalanceBaseUnits, outflowsBaseUnits, startAnchor, endAnchor. Anchors include the chain/finality fields above and a canonical blockHash (Solana slot/block identifier). Amounts are canonical unsigned base-unit strings. Snapshot state is immediately before each window boundary, on finalized canonical history. Aggregate all Solana token accounts owned by the receiving wallet. Native-asset outflows include network fees; token outflows use actual balance reductions, including applicable token fees. No receipt can compensate for another asset's discrepancy. `integrity::reconcile` requires `inbound = end - start + outflows` exactly for each asset/wallet and refuses missing, duplicate, same-provider or same-evidence records.
7. Create `INPUT_MANIFEST.json`: `{ "files": { "config": "config.json", "bindings": "bindings.json", "transfers": "transfers.json", "prices": "prices.json", "reconciliation": "reconciliation.json" }, "evidenceFiles": ["primary-raw.json", "independent-raw.json"] }`. Paths resolve relative to the manifest. The evidence hashes must match the source descriptors. `node scripts/feast/score.mjs INPUT_MANIFEST.json OUTPUT_DIRECTORY` validates everything before creating output or writing CSV. Its report records SHA-256 of the manifest, each five input files and every raw evidence file, provider/dataset descriptors, balance evidence and the clean scorer Git commit. Publish those exact inputs, report and CSV/hash.
8. Compare the CSV to onchain allocation entries; pass its exact 32-byte hash to `feast::set_allocations` and `finalize`. `finalize` enforces matching hash, seven days since the last edit, full locked reward capacity and surplus burn. `claim_locked` consumes reserved rewards even during emergency pause or before the ordinary vault opening.

Trust assumptions: independently fetching complete canonical datasets, provider independence, truthful timestamp/balance/outflow extraction, raw-to-normalized correspondence, CSV-to-onchain correspondence, and archive availability still require operator review. The scorer checks data consistency and refuses malformed or unreconciled inputs; it is not a cross-chain indexer, light client or cryptographic proof of provider honesty. Authenticate and review both providers. Do not open any source network before its export/finality/balance adapters are rehearsed.

## Deterministic rules

Window is [start, start + 21 days). Days 1–5 multiply by 1.50; each subsequent day's step falls linearly from day 5 to day 19, where it reaches 1.00; days 19–21 remain 1.00. Liquid, 12-month and 24-month choices multiply by 1.00, 1.10 and 1.25 respectively. Every source bound to one Sui destination must choose the same term.

Price is the lesser of confirmation-time spot and the arithmetic average of 1,440 preceding one-minute as-of Pyth observations. Each must be no more than 60 seconds old at its sampling time. This sampled average is not a continuous time-weighted average. USD prices/values use eight decimals, amounts use native token decimals. Integer arithmetic rounds down; points use a common denominator of 280 so the declared multipliers are exact.

Each wallet receives the lesser of its proportional 100M-pool allocation and 10,000 V1PR per USD before multipliers. No per-wallet cap applies. Rounding and the price floor can leave inventory, burned at finalization. CSV is sorted by normalized Sui address with LF newlines; SHA-256 hashes its exact bytes. Clearing price is total eligible USD divided by total allocated V1PR, published as an exact rational. receivedBaseUnits in results.json contains scored eligible receipts; treasuryReceivedBaseUnits includes all exported accepted-coin Foundation receipts in the window, including unbound sources. Neither is a live balance or independent all-transfer index. Archive all receipts. Results also record windowStart and the current Git commit; execute from a clean, committed scoring release so that commit identifies the code that actually ran.

Trust assumption: the DEX pool is intended to open at no less than the Feast clearing price, paired with 25% of Feast proceeds. Remaining proceeds are founder-controlled and discretionary. This is an operating commitment requiring funding, exchange transactions and receipts, not an automatic cross-chain contract restriction.


For the monitor, copy exact results.json bytes to public/feast-results.json and configure their SHA-256 as feastResultsSha256. Publish all archives alongside the report.

The release requires liquidityProceedsPercent to be exactly 25 and distinct accepted-coin IDs. Both received-total maps contain all ten IDs, including explicit zero values for coins with no exported receipts. The monitor rejects omitted asset totals, eligible receipts exceeding all received receipts, mismatched allocation/burn totals or a clearing-price fraction that differs from the scored USD and allocation. A file hash identifies published bytes; it does not establish complete indexing or canonical receipt validity. CSV address ordering uses binary lexical comparison, independent of the machine's locale.


## Timeline

Applications for the separate free-claim pool run [T-7 days,T); approvals freeze at T, and free claims close at T+14 days. Feast transfers are valued by qualifying confirmation in [T,T+21 days); send early enough to confirm before cutoff. Publish all scoring inputs and allow at least seven days of review before finalization F. feast::finalize requires the matching committed hash and seven days since the last edit; every edit restarts that timer. Liquid vesting is 50% at F and fully vested by F+60 days; all Feast claims close at F+90 days. Paired liquidity and LP custody must be verified before trading opens. See docs/WHITEPAPER.md and scripts/claims/README.md.

Official native-asset references: https://dogecoin.com/ and https://docs.memecore.com/memecore/token/usdm ; network details: https://docs.memecore.com/memecore/connect-to-memecore . Dogecoin signed-message compatibility follows https://github.com/dogecoin/dogecoin/blob/master/src/rpc/misc.cpp .


## Trust assumptions

Cross-chain finality, complete exports and historical-price provenance; correct CSV publication and AdminCap allocation entries; original-work eligibility review and intake timestamps; receipt publication and multisig custody; 25% proceeds conversion/funding, exchange opening-price floor and LP locking; discretionary Foundation/Community budgets; and deployment/source correspondence are operator responsibilities, not restrictions imposed by Move. See the white paper section 11 for the full list. Contract rules are enforced by feast::set_allocations/finalize/claim_locked/burn_unclaimed (hash, review, reservations and expiry), lock_vault::open/deposit (opening and emergency pause), free_claims::schedule/approve/claim (one-time claim dates/caps) and launch::allocate (custody and once-only allocation).

## Authenticated pre-opening Pyth gate

Run `npm run check:pyth` with PYTH_BENCHMARKS_API_KEY configured only in the operator environment. It queries all ten frozen feeds at 12:00 UTC on 29 September, 30 September and 1 October 2026, requiring all 30 authentic historical points. It checks feed identity, positive price, exponent, a non-future observation at most 60 seconds old, and raw-response SHA-256. Requests are paced to the documented limit. Only a complete successful live run writes `tests/fixtures/pyth-historical.json`; commit and independently review that archive before opening contributions. Do not commit request headers or credentials.

`npm run test:pyth` checks seven synthetic success/failure cases and verifies the live archive if present. Passing synthetic tests does not satisfy the live gate. At this iteration's local check, the API key was unavailable and no live historical-price fixture was generated. Authenticated feed coverage remains unverified. See [Pyth historical data and authentication](https://docs.pyth.network/price-feeds/core/use-historical-price-data). Thirty historical points establish basic coverage, not correctness of every 1,440-minute campaign price series; actual scoring must validate and archive that entire series.
