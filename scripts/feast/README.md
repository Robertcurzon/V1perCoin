# V1PR Feast scoring

The curated accepted list is SHIB, PUMP, PEPE, DOGE, PENGU, SPX, BONK, FLOKI, WIF and MemeCore M in config.json. DOGE is native Dogecoin (eight decimals); M is native MemeCore mainnet, chain ID 4352 (18 decimals). Ethereum and Solana assets use exact contracts. The archived market snapshot is provenance, not an automatic selection rule. Pyth DOGE/USD and M/USD feeds are archived and verified. Wrapped substitutes are not accepted. No campaign is open: windowStart and all four Foundation receiving addresses must come from real launch records.

The V1PR Foundation (founder-controlled) receives contributed coins. Publish Ethereum, Solana, Dogecoin and MemeCore receiving addresses before any signatures or transfers, with chain-appropriate custody. Never substitute a Sui address for a source-chain destination. Native DOGE bindings use P2PKH source addresses; DOGE receiving custody may use P2SH multisig.
## Reproduce

1. Copy config.json into an input JSON object as `config`; set the real Unix-second windowStart and published Foundation addresses. Freeze and publish this configuration before opening the 21-day campaign.
2. Add `bindings`, `transfers`, and `prices` arrays/object. Bindings contain chain, windowStart, source, sui, lockMonths (0, 12, 24), message, signature and lockSignature. Both messages use the exact canonical text from networks.mjs: `Bind <source address> to Sui <sui address> for the V1PR Feast`, newline `Source network: <chain>`, newline `Campaign start: <windowStart>`. The second also appends newline `Lock choice: <months> months`. Include windowStart in each binding; the scorer rejects network/campaign replay. The second signature prevents substitution of the chosen term. Ethereum and MemeCore EOA personal-sign, Solana Ed25519 and Dogecoin compact Base64 signatures with the Dogecoin signed-message prefix are supported. Native DOGE signatures are imported manually and verified against an independent test vector using the existing noble secp256k1 primitives. Contract-wallet signatures are not supported.
3. Export every finalized transfer from bound sources to the Foundation. For native DOGE/M, contract is the literal `native`, never a token address. Each record contains chain, contract, from, to, amountBaseUnits (integer string), confirmedAt (Unix seconds), txHash and index (unique event/instruction index). DOGE additionally requires all inputAddresses to equal the bound P2PKH source, a 64-hex txid, output index and at least 60 confirmations. M requires chainId 4352, receiptStatus `success`, receiptKind `native-transfer` and finalized true. Independently verify canonical receipts, finality and export completeness; this scorer does not run an indexer or establish chain finality. Archive and publish receipt provenance and all Foundation transfers, including excluded ones.
4. With authenticated historical access available, run `node scripts/feast/fetch_prices.mjs INPUT.json PRICES.json`. Set PYTH_BENCHMARKS_API_KEY only in the operator environment. Merge the output's prices into INPUT.json and archive rawArchive. The authenticated endpoint remains a launch rehearsal requirement: unauthenticated testing returned HTTP 401. Never open contributions until historical coverage is verified. Missing, stale or future data is a hard error.
5. Run `node scripts/feast/score.mjs INPUT.json OUTPUT_DIRECTORY`; run `npm run test:feast`. Publish the exact input, price archive, results.json, allocations.csv, allocations.sha256 and the scoring script Git commit. Protect signatures against reuse by freezing this campaign's bindings. Bindings publicly link source wallets to Sui destinations.
6. Compare totals independently, pass CSV amounts (six-decimal V1PR base units) and lock_months to feast::set_allocations, publish its digests, then finalize once. Onchain finalization burns the unallocated remainder.

## Deterministic rules

Window is [start, start + 21 days). Days 1–5 multiply by 1.50; each subsequent day's step falls linearly from day 5 to day 19, where it reaches 1.00; days 19–21 remain 1.00. Liquid, 12-month and 24-month choices multiply by 1.00, 1.10 and 1.25 respectively. Every source bound to one Sui destination must choose the same term.

Price is the lesser of confirmation-time spot and the arithmetic average of 1,440 preceding one-minute as-of Pyth observations. Each must be no more than 60 seconds old at its sampling time. This sampled average is not a continuous time-weighted average. USD prices/values use eight decimals, amounts use native token decimals. Integer arithmetic rounds down; points use a common denominator of 280 so the declared multipliers are exact.

Each wallet receives the lesser of its proportional 100M-pool allocation and 10,000 V1PR per USD before multipliers. No per-wallet cap applies. Rounding and the price floor can leave inventory, burned at finalization. CSV is sorted by normalized Sui address with LF newlines; SHA-256 hashes its exact bytes. Clearing price is total eligible USD divided by total allocated V1PR, published as an exact rational. receivedBaseUnits in results.json contains scored eligible receipts; treasuryReceivedBaseUnits includes all exported accepted-coin Foundation receipts in the window, including unbound sources. Neither is a live balance or independent all-transfer index. Archive all receipts. Results also record windowStart and the current Git commit; execute from a clean, committed scoring release so that commit identifies the code that actually ran.

The DEX pool opens at no less than the Feast clearing price, paired with 25% of Feast proceeds. Remaining proceeds are founder-controlled and discretionary. This is an operating commitment requiring funding, exchange transactions and receipts, not an automatic cross-chain contract restriction.


For the monitor, copy exact results.json bytes to public/feast-results.json and configure their SHA-256 as feastResultsSha256. Publish all archives alongside the report.

The release requires liquidityProceedsPercent to be exactly 25 and distinct accepted-coin IDs. Both received-total maps contain all ten IDs, including explicit zero values for coins with no exported receipts. The monitor rejects omitted asset totals, eligible receipts exceeding all received receipts, mismatched allocation/burn totals or a clearing-price fraction that differs from the scored USD and allocation. A file hash identifies published bytes; it does not establish complete indexing or canonical receipt validity. CSV address ordering uses binary lexical comparison, independent of the machine's locale.


## Timeline

Applications for the separate free-claim pool run [T-7 days,T); approvals freeze at T, and free claims close at T+14 days. Feast transfers are valued by qualifying confirmation in [T,T+21 days); send early enough to confirm before cutoff. Publish all scoring inputs and allow at least seven days of review before finalization F. Its timing is operator policy, not enforced by feast::finalize. Liquid vesting is 50% at F and fully vested by F+60 days; all Feast claims close at F+90 days. Paired liquidity and LP custody must be verified before trading opens.
