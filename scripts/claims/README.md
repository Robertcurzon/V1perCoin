# V1PER free-claim eligibility

Budget: 100M existing V1PER. Maximum 10,000 distinct addresses, 10,000 V1PER per address once (0.001% of initial supply each). No payment, referral purchase or legal identity upload is required. This enforces a wallet/entry limit, not one human per allocation.

1. Publish the reviewed release, day-0 UTC opening T and official HTTPS submission channel. Call free_claims::schedule once, at least seven days ahead. The contract sets the 14-day exclusive deadline and cannot reschedule, extend or reopen it. The shared opening is also the Feast's T.
2. Receive signed applications during [T-7 days,T). The website downloads an application file; it does not submit it. The official channel adds receivedAtMs from its own receipt log, never a claimant-selected timestamp. Publish receipt provenance. Applications contain address, entryUrl, signature. startMs in the submission must match the campaign. Sign the exact text from messages.mjs; wallet signatures authorize no transfer.
3. Review one original meme, useful guide or valid testnet issue report for authorship, originality and duplicates. Record each application's decision, reason and SHA-256 of its archived content as a review (address, entryUrl, entryHash, accepted, reason). Archive the content so hashes can be checked. Reviews are discretionary; applicants are not automatically eligible.
4. Build INPUT.json with startMs, applications and reviews. Run `node scripts/claims/prepare.mjs INPUT.json MANIFEST.json` and `npm run test:claims`. This verifies Sui personal-message proofs, the seven-day receipt interval and complete reviews. Accepted applications are ordered by recorded receipt time, then address and link. It deduplicates wallet, normalized link and content hash, and caps output at 10,000. Operator review and receipt timestamps are trusted inputs, not facts the script independently discovers. No private keys are generated or used.
5. Publish manifest, archived entries, receipt provenance, input hash and code commit. Approve its addresses with the scoped AdminCap before T, publishing every approve digest and reconciling the complete eligibility table. The script sends no chain transactions. Onchain approvals reject zero/duplicate addresses and over-capacity batches; after T they are forbidden. Approval is irrevocable, so check the manifest before sending it.
6. In [T,T+14 days), each approved transaction sender claims exactly once and pays network gas. At or after the deadline, anyone may burn unclaimed tokens; the administrator cannot take or recycle them. There is no second free round. Existing lock rights and the separate Feast window continue under their own rules.

Multiple identities can still submit different entries. Manual review can reduce obvious copying or farming but is not a cryptographic identity system. Published wallet proofs and entries are public; privacy means pseudonymous participation, not anonymous claims.
